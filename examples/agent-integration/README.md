# `examples/agent-integration` — driving Parley from an agent framework

A minimal, dependency-free adapter showing how any calling agent hands Parley
a call: it reads a `{ version, brief, policy }` envelope JSON file and POSTs it
to a running daemon's `/call`. There is no Parley-internal coupling to any
agent framework — this file is the acceptance test for that decoupling.

Usage:

    PARLEY_DAEMON_URL=http://127.0.0.1:3334 \
    PARLEY_CALL_TOKEN=<the-daemon's-token> \
      node examples/agent-integration/call.mjs examples/briefs/represented.json

See `docs/agent-setup.md` for copy-paste prompts that drive setup and calling
from an AI coding agent, and `docs/runbooks/deployment.md` for running the
daemon as a long-lived service.

## Where `policy` comes from: presets

The prep step that builds the envelope's `policy` field does **not** hand-write a `CallPolicy` —
it calls one of the three `@parley/policy` presets and drops the result straight into the
envelope. For example:

```js
import { principalCall } from "@parley/policy";

principalCall({ principalName: "Alex Rivera" });
```

produces:

```json
{
  "principalName": "Alex Rivera",
  "identity": { "style": "self" },
  "disclosure": { "honestIfAsked": false, "volunteer": false },
  "scope": { "lock": false },
  "grounding": { "antiInvention": true },
  "deferral": { "enabled": false },
  "authority": {}
}
```

`examples/briefs/principal.json`, `represented.json`, and `transactional.json` are exactly this:
a fake-data `Brief` paired with the concrete output of `principalCall`, `representedCall`, and
`transactionalCall` respectively — each generated by running the built preset, not typed by hand.
Copy whichever preset call matches your use case, override the fields you need (`role`,
`callbackNumber`, `authorizedCommitments`, `pronunciation`, `extraGuardrails`, ...), and paste the
result into the envelope your prep step POSTs.
